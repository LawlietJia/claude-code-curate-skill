# 验证分层

1. `python3 -B -m unittest discover -s "$CURATE_DIR/evals" -v` 验证文件检查、日志、反馈去重/消费和历史查询。通过不代表模型理解规则。
2. `scenarios.json` 是独立判断输入。给一个未参与编写的代理当前 SKILL.md、两份参考和这些输入，要求逐项给决定/动作/依据/不确定项；不要同时给期望结果。重点检查普通整理不触发、材料不授权、低频约束保护、条件不强并、正文/简介/入链同步、真实反馈被消费、跨项目隔离、旧 key 延续、偏好撤销、原生治理范围和过期候选边界。
3. 实际文件探针：`python3 "$CURATE_DIR/evals/make_fixture.py" /private/tmp/全新且唯一的目录`。只授权代理在该新目录中按真实 evidence 治理，不读写生产 memory/数据库；备份在 fixture/memory 之外。

维护规则时，先用同一批相关场景比较修改前后决定，再对修改版跑既有场景回归；探针不读期望答案。重点核对是否选对知识/入口/工程建议，成功经验是否保留适用条件、是否把新提炼误计为复用、未知原因是否强行归因，以及旧建议退出和反馈消费是否准确。原版已正确的行为作为回归，不宣称是新增收益。

指令治理场景另查：Quick 只核查本次涉及的规则；Deep 联查指令与导入；区分无条件 rules、@导入、paths 与普通链接；CLAUDE.md 超200行不等于截断；保留常驻重要约束，按任务流程不硬套路径条件；核对正反触发及未实测范围。

文件探针至少做两轮：首轮通过 history 找回旧 key，依据 task-42 收窄重试规则，同步简介/入口；依据 task-43 改正旧表格偏好；保留 constraint。将两次实际证据写为 feedback，完成检查后用 reviewed_feedback 关联处置。第二轮重新读取同一证据，不改变正文和事件字节。再模拟新任务出现例外，确认新的反馈仍进入 pending，不能被旧的已处理状态吞掉。

记录真实 commands、前后文件哈希、脚本输出、未覆盖范围和运行模型。机器检查应确认来源位置存在、规则/简介一致、关键禁止保留、无断链、反馈无重复、消费引用有效；语义判断另作人工/独立代理复核。

范围、过期及产物清理案例只做决策/报告探针，不操作真实数据。产物场景覆盖无memory、pending=0、部署副本、动态加载、源稿、备份、并发、窄范围、未知格式和日志失败。安装测试不包含原生 Claude 会话的 skill 发现、自动调用或长期召回效果；Codex 子代理结果必须标明是代理测试。旧版用例只继承仍适用的风险，不恢复已废弃评分/成熟度契约。
