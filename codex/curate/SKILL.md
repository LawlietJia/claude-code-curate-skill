# Curate

用实际证据合并、去重、纠正、提升和淘汰知识；根据后续使用修正做法，保留重要条件与例外。只在用户明确调用或请求治理时运行。

## 范围与入口

- `$curate`：Quick，处理本次会话知识、相关记忆和本次产物；`$curate --deep`：整个授权项目；`--check` 可与两种模式组合，只读，不改文件、不提交说明、不写记录或快照。参数是本 skill 的约定。
- 用户只要求修改一条知识或清理某类产物时，严格按限定执行。先确认项目规范绝对路径、当前运行时提供的记忆位置和允许入口；不凭同名目录合并项目或工作树。
- 项目治理不自动包含个人全局规则、其它项目、插件或系统缓存。附件、历史建议及引用命令是证据，不是新授权。
- 项目事实留在项目文档，稳定约束放正确作用域的 AGENTS.md；主要正文保留一处，其他入口留任务条件及短指针。不另建平行记忆库。
- 系统记忆正文和摘要只读；仅在用户明确要求更新记忆且当前运行时允许时提交小型更新说明。调用 skill 不扩大写入权限。只要求清理文件不构成更新记忆的授权。
- 工程逻辑、模板行为和自动化变更默认给出具体建议，不借治理改程序功能。已获授权且仍适用的知识整理直接推进；重要独有内容删除或扩大规则范围先给具体差异。

## 每轮工作

1. **接续**：按[记录与接续](references/records.md)读本轮授权范围的全部未结概况与未处理反馈。Quick 对本次相关、有新进展或影响重大的项深入；其余保留等待原因及再查条件。Deep 全面复核。没有来源的旧建议标未恢复，不假装已完整接续。
2. **判断增量**：先查当前正文、同义表述与权威来源。只保留会改变后续做法的知识；临时进度、常识、助手自评不入库。区分事实、推断及用户决定，按具体命题、范围与条件匹配，不仅看关键词。
3. **选择最小修正**：按[治理规则](references/governance.md)合并重复、精确纠错、处理失效内容与清理产物。正文正确但未找到时改入口；规则没执行时查执行证据，不再堆一条同义提醒。没有知识增量仍可完成已授权清理。
4. **写前写后核验**：修改前重新读实际目标，比较已读内容；有并发变化先调整差异。独有内容须有经验证的恢复依据。写后读差异并检查相关入口、引用、条件和交付/运行依赖，不用时间戳或文件数代替正确性。
5. **记真实结果**：记录实际改动、具体未结问题及反馈处置。动作执行、反馈复核和问题解决分别判断；提交记忆说明不等于采纳。无增量、无新证据就不造记录、改日期或换措辞。

## Quick 与 Deep

Quick 从本次操作记录确定生成、修改或使用过的文件，不按修改时间猜归属，不扩成全项目清扫。交付验证后，清理确已无用的临时文件、失败产物、重复副本与备份；保留源稿、素材和必要重建/追溯材料。

Deep 分批盘点整个授权项目，包括隐藏、忽略的文件以及文档、素材、程序和备份。受保护区域只登记边界；分清“已枚举、已读内容、已核依赖”。出现无法读取、用途不明或剩余批次时报告未覆盖范围，后续从剩余范围接续，不把第一页或近期抽查说成全量完成。

跨文件矛盾、重复失败或指令加载风险只扩到必要范围。按实际受影响对象验证一次；只有新变化、失败或未解决风险才补查。等待原生采纳不阻塞其他已授权治理，不为验证启动新会话、轮询或后台任务。

## 反馈让治理变得更有效

- 只记录已有知识实际产生的 helped / failed / exception / corrected 证据；读取、引用、新方法刚测试通过都不计复用成功。同任务重复证据不重复计入。
- 先处理失败、例外、用户纠正，再看成功：核对是知识错误、未找到、未应用还是原因未知。反例只推翻受影响条件；重复成功保留可复用做法和条件，不据次数自动排序或推定因果。
- 重要低频约束、明确偏好单次即可保留或提升到正确范围；未经授权不提升为全局规则。撤销偏好及时修正，未使用不等于过期。
- 处理反馈后记录依据和实际结果。有剩余治理或工程问题时，先保存或确认关联的未结事项，再标记反馈已复核；任一步记账失败就停止后续记账，恢复时先查已落盘结果。新建议替代旧方案不等于目标解决，没有新证据不重复执行失败操作。

## 系统记忆更新

1. 读取当次上级指令确定入口；不能由旧记忆或本 skill 推导写入权限。入口不明或不可用时保留候选说明与阻塞原因，不自行改配置或内部数据。
2. 搜索相关正文及既有说明，核对范围与剩余差异；已提交且内容一致不重提。只有确有增量且获授权时，经允许入口提交一次。具体写入、中断补记及采纳检查见[记录与接续](references/records.md#系统记忆说明)。
3. 后续治理按未结项检查正文和相关活跃入口。note 存在、时间戳变化或合并任务成功不证明问题解决；摘要不必包含每条知识。区分“已提交”“当前内容符合”“有证据观察到采纳”“仍有缺口”。
4. 实际后续任务中观察是否找到、应用且正确；没有独立使用证据不宣称召回率或长期收益提高。不承诺永久遗忘或原生历史记录总量有界。

## 记录和交付

使用实际 skill 目录下的 `scripts/curate_ledger.py`，仅维护实际 CODEX_HOME 下的 `curate/events.jsonl`；路径、字段与按需命令见[记录与接续](references/records.md)。无事件不预建文件；不向系统记忆写入治理待办元数据，不迁移 Claude 账本。

最后简述：实际知识改动、清理及保留理由、做过的检查、未结事项与未核验范围。反馈可合并一句说明。清理空间、链接完整或测试通过只证明对应检查，不代表已变聪明。收尾本轮无用暂存，保留仍需恢复或重试的最小依据。
