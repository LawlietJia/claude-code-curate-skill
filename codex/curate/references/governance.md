# 知识、指令与产物治理

## 知识判断

| 证据 | 最小动作 |
|---|---|
| 同范围、同条件的事实已存在 | 不新增、不更新日期；需要时修检索指针 |
| 相近表述但条件或例外不同 | 保留分支，不强并 |
| 等价重复 | 留一个主要正文，保留来源和独有条件，修复活跃入链 |
| 来源冲突 | 比较权威性、适用范围和实际验证，不仅按日期选；不明则未结 |
| 新证据推翻部分结论 | 只替换该部分，不删仍有效内容 |
| 正确但找不到 | 查任务词、同义词、入口及可见范围，改短指针而非复制全文 |
| 已找到但没执行 | 查已有流程/检查的实际覆盖；提最小工程建议，不继续叠提醒 |
| 明确偏好、稳定约束、高代价教训 | 即时保留；需要常驻时放正确范围，不等待次数阈值 |
| 版本、路径、环境等易变事实 | 优先留权威复查方法和使用条件，不积累状态快照 |
| 到期承诺、临时结论、旧建议 | 核实已完成、失效或需延续；完成后收缩成当前做法 |
| 错误、失效或已替代 | 移除活跃结论及冲突入口；有恢复/审计价值的证据与有效规则区分 |
| 少用、年久、无法核验 | 不据此删除；必要时在高风险使用前检查 |

每项知识应能说明下次什么任务会用、依据在哪里、哪些条件成立。保持来源原有时间精度；相对日期只有在来源时间明确时才换算，不能用文件修改时间猜测。

知识存放沿用已有项目结构，无必要不新建文件。领域事实留权威文档，重复步骤若可由既有检查稳定处理，提出复用检查的建议；仅“可以有一个工具”不是建设理由。程序或模板的功能修订另按用户授权实施。

## AGENTS.md 与按需读取

- 先看本次实际提供的指令和有效配置，核对项目根到工作目录的继承链、AGENTS.override.md 的覆盖，以及配置中的 fallback 名称。只看 AGENTS.md 自身长度可能漏掉覆盖或累积问题。
- 加载预算按实际 `project_doc_max_bytes` 的字节口径检查；没有取得当前限制时明确未核验，不套用 Claude 的 200 行阈值。统计文件字节不等于实测加载；不为通过检查擅自提高预算或改配置。
- 先去除重复与失效内容。每次必须遵守的少量稳定约束保留在实际生效的正确范围；任务专用长流程放现有手册，入口写清“何时读、读哪里”。普通链接要由代理按条件读取，不等于自动加载。
- 嵌套 AGENTS 适合目录范围，不等于任意任务自动匹配。将规则移到子目录前，核查原本应覆盖的任务仍能取得规则。`rules.md` 文件名、Claude 的导入语法和规则目录都不在此默认获得原生语义。
- 拆分后核对条件、例外、相对路径和活跃引用；用一项应适用和一项不适用的任务检查入口。只做了静态检查就如此报告，不为证明加载而自动开启真实新会话。

## 产物清理

清理涵盖各类文件，但仅处理已授权范围。逐项或对同理由的一组候选核对：当前用途、使用者/依赖、独有内容、交付/编辑/运行/重建/追溯/回退价值，以及可删除的具体依据。

- 本任务已结束且无使用者、无独有内容的失败暂存、临时清单和可重建缓存，可以清理；项目外临时文件还须证明属于本任务。系统重建的缓存不反复追删。
- 同名、同哈希、年久、Git 忽略或搜索无引用都只作线索。相同内容可能各自用于部署或交付，程序相似不等于可合并。
- 最终导出稿不能替代可编辑源稿、原始素材或重建程序。无法读取的格式只列未核验，不按扩展名删除。
- 备份须确认内容已被可访问且经核验的副本完整覆盖、无独立回退用途；唯一恢复副本或未提交的独有内容保留。Git 跟踪状态本身不保证可恢复。
- 默认保护 Git 内部数据、依赖和运行环境、数据库、插件数据、原始会话及系统记忆内部文件。只登记边界，不展开清理；不卸载软件或清系统全局缓存。
- 枚举前先确定并排除受保护目录，不先递归列出其内部再过滤；符号链接只登记自身。校验范围同样不沿外部链接扩张。
- 链接目标不随扫描扩大范围。删除链接本身也先核用途；不跟随链接递归删除。候选在删除前重查路径、类型、内容和使用状态，目录变化则重新核验，不能套用旧清单。
- 在授权文档、代码和配置中查名称、路径、别名和调用入口，结合动态加载、外部消费方及运行占用核实；修复活跃引用。证据不足保留并说明缺口，低风险且授权充分的清理不重复请示。

## 修改、恢复与验收

改动独有内容前保留经核验的恢复依据：完整原文、位置和指纹；已有可恢复版本就复用。可丢弃、可重建且无独有内容的产物不为删除再造备份。需要可恢复删除时，遵守平台可用方式和本次授权，不能用备份存在替代授权。

写前重新核对原文或指纹，发生并发变化先重读；逐文件精确修改。写后核对保留内容、引用、重要例外及实际受影响的交付/运行入口。不是每次治理都跑整个项目测试；只跑改动涉及的必要检查，失败后针对具体风险补查。

检查或记账失败时说明实际已改哪些、剩余什么；不能报全成功或盲目重复动作。结果一致且检查足够时结束，不为文件数量、整齐程度或评分追加机制。

## 删除与遗忘

区分清除活跃知识、保存必要证据和永久遗忘。用户要求不再使用某项时，核查授权范围内正文及入口，对系统记忆提交最小撤销说明；不要在记录或说明里复制敏感原文。历史 notes、原始证据和内部库不能由普通治理删除。范围外的再生成来源或产品未支持的删除要报告限制，不承诺从所有系统彻底遗忘。
