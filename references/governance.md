# 治理规则

| 情况 | 动作 |
|---|---|
| 相同事实已存在 | 不新增，不刷新知识日期 |
| 知识正确但未找到 | 核对入口的任务条件、关键词、指向及可见范围；修短指针，保留唯一正文，不以复制或扩大加载范围代替 |
| 已有规则未执行或检查漏检 | 核对已有手册、模板与检查的入口、实际执行和覆盖证据；针对缺口提工程建议，不叠加同义提醒或重复造工具 |
| 等价知识重复 | 保留一个主要正文及来源、条件，修复全部活跃入链；运行/部署文件另按下节判断 |
| 同词不同条件 | 保留条件分支和必要例外 |
| 来源冲突 | 比较权威性、范围及实际验证，不仅按日期选择；无法判断则标未决 |
| 新证据只推翻一部分 | 精确替换该部分，保留仍有独立依据的内容 |
| 明确偏好、稳定约束、高代价教训 | 单次即可保留；需要每次遵守时提升到正确范围 |
| 易变路径、版本、环境状态 | 留复查入口及触发条件，使用前核验 |
| 到期承诺、临时观察或旧改进建议 | 到期核验是否完成、失效或需延续；发现建议已落实时合并为当前做法，清除过时状态，保留有效条件、例外和必要原因 |
| 已证实错误、失效或被替代 | 清除活跃结论和入口；无独立价值的旧文按授权可恢复删除 |
| 无法验证 | 标明未知，高风险使用前核验，不直接当错误删除 |

## 存放与提升

- 项目事实和手册放项目文档，memory 留必要经验与检索入口；易查的环境事实优先留权威查询入口，保留环境本身没有说明的条件、原因和陷阱。
- 工程建议说明问题证据、现有机制、最小改动与验证方法；只有缺少工具而无实际问题，不构成建设理由。能稳定判断的重复错误优先建议复用已有检查，以原失败样本和正常样本验证有效性；主观质量保留适当人工判断，不承诺自动化替代。
- 建议随回复提供或复用现有交接/待办文档；不新建常驻建议库或承诺跟踪提醒。后续相关新证据再核验，未实施本身不触发重复治理。
- 强制规则放正确项目/路径范围的 CLAUDE.md 或 `.claude/rules/`；全局提升须有全局授权及跨项目依据。
- 提升后保留一个主要正文，原处只留必要指针和使用条件。精简指令依据重复、失效或实际行为证据，不凭“模型应该知道”删除稳定用户约束。
- 更新正文时同步现有 description、MEMORY.md 摘要和其他活跃入口，不批量增加空元数据。
- 具体事件、状态核验及截止时间使用有依据的绝对日期或区间；只知年月就保留原精度。相对日期按明确的来源时间和时区换算；无锚点标日期不明，不用文件修改时间推算。保留滚动窗口、周期条件及必要原文引用。

## 指令体量与按需加载

- 按 Quick/Deep 的授权范围核对实际生效的指令、继承关系、`@` 导入和规则条件；分别看单文件与会一起加载的内容，不为检查扩大到其他项目或修改全局规则。
- CLAUDE.md 以 200 行作为精简复查参考，不当作截断线或强制拆分门槛；未超行也查重复与无关常驻内容。先删重复、失效内容，再按用途分放；没有实质收益就保留原结构，不机械分片。
- 每次必须遵守的核心约束保留在原授权范围内的常驻位置。仅针对明确目录/文件的规则可放 `.claude/rules/主题.md`，用 YAML frontmatter 的 `paths` 限定，例如 `paths: ["outputs/slides/**"]`；触发不能覆盖适用场景时保留原加载方式，不为减量缩小约束。
- 按任务触发、无法按文件路径限定的详细流程放现有手册或合适的现有 skill；在入口写明何时读、读哪里，例如 `编写月度研究报告前，读取 [研究流程](docs/research.md)`。普通链接由代理按条件读取，不保证原生自动加载；拆分不要求新建 skill 或规则目录。
- 单个 `rules.md` 文件名无特殊加载作用；无 `paths` 的 `.claude/rules/*.md` 与 `@` 导入通常仍随对应入口加载。它们可用于组织内容，不能据此宣称减少常驻上下文；按需正文不要再被常驻入口 `@` 导入。
- 拆分后逐项核对约束、条件及例外未丢失，修复旧入口和相对路径；用应触发与不应触发的代表文件/任务核对路径条件和读取入口。检查 YAML 及路径模式有效性，不能把解析失败当按需加载。用途或加载行为不明时保留原规则，列出待核验项。
- 比较拆分前后常驻内容及代表任务需要读取的内容；可用原生会话时核验加载，未实测时明确仅做静态核查。链接完整、主文件变短和 memory inspect 成功都不证明触发或减负生效；沿用现有日志和输出，不另建规则清单或评分账本。

## 产物清理

- 对候选逐一核对：是否仍用于交付、编辑、运行、重建、追溯或回退；是否仍被文件、配置、代码、流程或其他任务使用；有什么证据证明已无独立用途。没有充分依据就保留并指出疑点。
- 任务已结束且无独有内容、无使用者的临时文件、失败暂存、可重建缓存可直接清理；文件名、扩展名、大小、年龄和 Git 忽略状态都只作线索。不卸载依赖、软件或清理系统全局缓存。
- 重复文件须核实内容和用途；同内容但不同部署位置仍可能必要。优先保留实际使用/交付的一份并修复引用，不改变必要路径契约。内容相似的文档先读语义和条件；程序相似不等于可合并，不借清理做功能重构。
- 最终导出稿不替代可编辑源稿、原始素材或重建程序。已有可用结果不证明中间文件都无用；缺少读取工具的格式只列未核验，不凭文件名删。
- 备份按独有内容及实际回退需要判断，不按年龄或固定份数淘汰。内容已由可访问且经核验的副本完整覆盖、又无独立用途的备份可删；唯一恢复副本或未提交的独有内容保留。Git 跟踪不等于改动已提交且可恢复。
- 默认保护 Git 内部数据、依赖/运行环境、数据库及插件数据；只登记范围，不深入清理。外部链接目标不随项目扫描扩张；需要删除的链接本身也须核对用途及授权。
- 无法确定当前是否有人使用、用途冲突或需删除独有重要内容时，保留并给具体处置建议；证据充分且已获范围授权的低风险清理直接执行，不重复询问。
- 完成核验与记账后，处理本轮临时清单、脚本和暂存，保留仍需重试的事件文件；仅保留必要结果、来源及回退依据，不额外生成常驻扫描清单、评分表或逐文件日志。缓存被系统重建不反复追删。

## 删除与遗忘

- 改动独有知识/文件前，在 memory 外保留完整原文、原位置及指纹；已有完整可恢复副本则复用。确认可重建且无独有内容或已由有效副本覆盖的可丢弃产物，不为删除再造备份。改后核对保留对象、恢复依据和活跃引用。
- 区分删除活跃知识、归档证据和永久遗忘；不要为了保留历史，让旧结论继续作为有效规则被引用。
- 用户要求永久不再记某项时，检查授权范围内的重复正文、入口及可能重新生成它的来源；需要撤销记录时写入既有合适位置。
- 删除来源仍需对应授权。范围外的来源只报告未处理，不扩展操作对象或承诺已从所有系统遗忘。
