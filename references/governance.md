# 治理规则

| 情况 | 动作 |
|---|---|
| 相同事实已存在 | 不新增，不刷新知识日期 |
| 等价重复 | 保留一个主要正文及来源、条件，修复全部活跃入链 |
| 同词不同条件 | 保留条件分支和必要例外 |
| 来源冲突 | 比较权威性、范围及实际验证，不仅按日期选择；无法判断则标未决 |
| 新证据只推翻一部分 | 精确替换该部分，保留仍有独立依据的内容 |
| 明确偏好、稳定约束、高代价教训 | 单次即可保留；需要每次遵守时提升到正确范围 |
| 易变路径、版本、环境状态 | 留复查入口及触发条件，使用前核验 |
| 到期承诺或临时观察 | 到期核验是否完成、失效或需要延续，并更新状态 |
| 已证实错误、失效或被替代 | 清除活跃结论和入口；无独立价值的旧文按授权可恢复删除 |
| 无法验证 | 标明未知，高风险使用前核验，不直接当错误删除 |

## 存放与提升

- 项目事实和手册放项目文档，memory 留必要经验与检索入口。
- 强制规则放正确项目/路径范围的 CLAUDE.md 或 `.claude/rules/`；全局提升须有全局授权及跨项目依据。
- 提升后保留一个主要正文，原处只留必要指针和使用条件。
- 更新正文时同步现有 description、MEMORY.md 摘要和其他活跃入口，不批量增加空元数据。
- 具体事件、状态核验及截止时间使用有依据的绝对日期或区间；只知年月就保留原精度。相对日期按明确的来源时间和时区换算；无锚点标日期不明，不用文件修改时间推算。保留滚动窗口、周期条件及必要原文引用。

## 删除与遗忘

- 改前备份完整原文及原位置，改后确认失效内容和活跃引用已清除。
- 区分删除活跃知识、归档证据和永久遗忘；不要为了保留历史，让旧结论继续作为有效规则被引用。
- 用户要求永久不再记某项时，检查授权范围内的重复正文、入口及可能重新生成它的来源；需要撤销记录时写入既有合适位置。
- 删除来源仍需对应授权。范围外的来源只报告未处理，不扩展操作对象或承诺已从所有系统遗忘。
